# Déploiement backend

L’image de `Dockerfile` écoute sur `PORT` (3000 par défaut) et nécessite `DATABASE_URL`. Configurer aussi `FRONTEND_URL` avec l’origine du frontend, sans slash final. `TRUST_PROXY_HOPS` doit correspondre au nombre exact de reverse proxies de confiance (0 par défaut) pour que la limitation des connexions utilise l’adresse cliente attendue ; ne pas faire confiance à des en-têtes proxy venant directement d’un client. Fournir ces valeurs via le gestionnaire de secrets de l’hébergeur.

Avant de démarrer la nouvelle version, appliquer les migrations depuis un job/outillage disposant des dépendances de développement du backend (`npm ci`, puis `npm run db:deploy`) contre la base cible. Le CLI Prisma n’est volontairement pas inclus dans l’image d’exécution. Pour Vercel, `npm run vercel-build` exécute `db:deploy` uniquement lors d’un build de production, puis compile l’application ; les builds Preview ne modifient donc pas la base de production. Vérifier que `DATABASE_URL` est configuré dans l’environnement Production de Vercel. Les seeds sont destinés au développement/démonstration : le seed automatique et l’endpoint de synchronisation refusent les déploiements de production (`NODE_ENV` ou `VERCEL_ENV`). Ne pas activer le seed de démo sur une base de production.

Les tags Git `vX.Y.Z` publient l’image `ghcr.io/<owner>/<repo>/backend`. Le workflow ne réalise pas de rollout automatique sur un hébergeur : voir la [documentation CI/CD du dépôt](../../docs/ci-cd.md).
